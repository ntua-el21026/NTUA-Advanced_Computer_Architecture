- Work section by section, following the organization used for exercises 1

- Preserve complete Sniper result directories and derive CSV/text summaries

- Treat simulator output as valid only when both the program-level protected

## Lock Implementations

- TAS-CAS repeatedly executes `__sync_val_compare_and_swap`.
- TAS-TS repeatedly executes `__sync_lock_test_and_set`.
- TTAS variants spin with ordinary loads while the lock is held and attempt
  their atomic operation only after observing `UNLOCKED`.
- All variants release through `__sync_lock_release`.
- Every program execution verifies `val == nthreads * iterations` and returns
  failure if mutual exclusion was violated.

## Build Outputs

- Real binaries use `bin/locks_<implementation>_real`.
- Sniper binaries use `bin/locks_<implementation>_sniper`.
- Generated binaries are ignored by Git.

## Sniper Container

- Pin the assignment's Sniper 8.0 image by digest:
  `sha256:4f10d4bbfee057e27a52fc0dc33087813feb504bbbfff22902984e356576eaed`.
- Build `advca-sniper:8.0` from `exercises/3rd/docker/Dockerfile`; the only
  added file is the supplied `advcomparch_mcpat.py`.
- Run orchestration with Python 3 on the WSL host. Individual Sniper and McPAT
  commands execute in disposable CentOS 6 containers.
- Run containers with the host UID and root group so benchmark outputs remain
  owned by the WSL user while `/root/sniper` remains accessible.
- The CentOS 6 image requires `vsyscall=emulate` on modern WSL kernels.
- McPAT uses `--no-graph`; report diagrams are generated by the repository's
  Python plotting workflow rather than the container's obsolete gnuplot stack.

## Section 4.1 Real-Machine Affinity

- The target laptop has 16 physical and 24 logical CPUs.
- Do not map software threads directly to logical CPU IDs `0..15`.
- Group logical CPUs by physical `(socket, core)` and select one
  representative from each physical core.
- Prefer SMT-capable cores first for the 1/2/4/8-thread subsets; use all
  physical cores for the 16-thread case.
- Record the exact topology and mapping in `machine.json`.
- Use repeated measurements and report the median. Calibrate a common
  iteration count so one-thread executions last several seconds.

## Section 4.2 Topologies

- `share-all`: L2 shared by 4, L3 shared by 4.
- `share-L3`: private L2, L3 shared by 4.
- `share-nothing`: private L2 and private L3.
- The full matrix contains `5 * 3 = 15` simulations.

- Supporting metrics: simulated runtime, total energy, average power, EDP, and
  ED2P.
- Real-machine results report median, mean, min, max, and standard deviation
  across repetitions.
